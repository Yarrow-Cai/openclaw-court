# 工作流

## 一、状态机

```
                  ┌──────────── 已驳回 ← 御史核验不通过
                  │
已立案 → 已派差 → 执行中 → 待签结 → 已签结
   │                 │
   │                 └────→ 已超时（过期限未回执）
   │
   └────→ 已撤回（大王收回旨意）
```

**终态只有三个**：`已签结`、`已驳回`、`已超时`（大王的 `已撤回` 另行记）。
任何停在中间态的任务，都视为**未完成**，太子不得回奏「已成」。

---

## 二、时序（一次完整差遣）

| # | 动作 | 执行者 | 产出 | 校验点 |
|---|---|---|---|---|
| 1 | 接旨 | 太子 | `job.json` | 有旨意原文、时间戳、编号 |
| 2 | 立案校验 | 御史 | 登记记录 | 六要素齐（见下） |
| 3 | 拆旨 | 丞相 | `dispatch.json` | 六字段齐全，验收可机器判定 |
| 4 | 派差 | 丞相 → 适配器 | 进程启动 | `dispatch.json` 存在 |
| 5 | 执行 | 差役 | `artifacts/<job-id>/*` | 进程退出 |
| 6 | 核验 | 御史 | `receipt.json` | 退出码 + 产物 + 摘要 |
| 7 | 汇总 | 丞相 | 汇总说明 | 与回执一致 |
| 8 | 回奏 | 太子 | 飞书消息 | 有 `receipt.json` 方可 |

---

## 三、立案六要素（缺一退回）

| 要素 | 例 |
|---|---|
| job_id | `JOB-20261023-001` |
| 旨意 | 原文照录，不许改写 |
| 下旨时间 | ISO 8601 带时区 |
| 请求人 | 大王（飞书 open_id） |
| 期望验收 | 可判定的条件（可空，由丞相补） |
| 状态 | `已立案` |

---

## 四、异常处理

### 4.1 差役失败（exit ≠ 0）

1. 御史记 `exit_code`，裁定 `驳回`
2. `驳回理由` 写清失败原因（取 stderr 末尾 20 行）
3. 丞相可**重新出差遣单**（同一 `job_id`，追加 `attempt: 2`）
4. 同一任务连续 3 次驳回 → 御史置 `已超时`，太子如实回奏，请大王定夺

### 4.2 超期

- 期限到点仍无产物 → 御史置 `已超时`，记录已过时长
- **不许**由太子或丞相自行延期；延期须大王准，记入 `job.json` 的 `延期记录`

### 4.3 产物不齐

- 验收条目与产物文件对不上 → 驳回，写明缺哪一条
- **御史不得代为补齐**（补了就是同谋）

### 4.4 差役进程失联

- 适配器负责落 `pid` 与开始时间
- 超期后由适配器 `kill` 并返回非零退出码
- 御史照 `exit_code ≠ 0` 处理

## 五、适配器契约

`adapters/<差役>.sh <dispatch.json>` 必须保证：

1. 读 `dispatch.json`，取 `任务` 与 `产物目录`
2. 执行，stdout/stderr **全部**写入 `artifacts/<job-id>/log.txt`
3. 产物写入 `artifacts/<job-id>/`
4. **以差役的退出码退出**（不得吞掉）
5. 不修改 `dispatch.json`，不写 `receipt.json`

```bash
#!/bin/bash
# 契约示意
set -o pipefail
DISPATCH="$1"
JOB=$(jq -r .job_id "$DISPATCH")
TASK=$(jq -r .任务 "$DISPATCH")
OUT=$(jq -r .产物目录 "$DISPATCH")
mkdir -p "$OUT"
pi "$TASK" 2>&1 | tee "$OUT/log.txt"
exit "${PIPESTATUS[0]}"
```

---

## 六、留痕要求

每一次差遣，最终应有四个文件：

```
jobs/<job-id>/job.json
jobs/<job-id>/dispatch.json
jobs/<job-id>/receipt.json
artifacts/<job-id>/log.txt
```

四件不齐，视为未办结。这是「无文书不办、无签结不奏」的落地形式。
